## Current implementation sequence

The next repository-only sequence is:

```text
1. Rule-of-Two chapter projection/requirement extraction
2. Contextual causal explanation on existing player decisions
3. Cross-domain Trait capability applications
4. Third heterogeneous chapter-scale composition
5. Bounded Copy strategy / player-authored routine priorities
6. Reconcile documentation and evidence ceiling
```

Each item must preserve existing canonical ownership and receive its own deterministic qualification inside Build Validation.

## Package 1 — Rule-of-Two chapter architecture

Compare Merchant District Crisis and Archive Inquiry and extract only concrete duplicated projection behavior. The expected smallest useful abstraction is a shared requirement-evaluation helper for existing chapter definitions/selectors.

This package must not introduce:

- a ChapterEngine;
- chapter-local canonical state;
- a generalized narrative condition DSL;
- a new save root;
- autonomous narrative progression.

## Package 2 — Contextual causal explanation

Explain why an already-available action is available using canonical evidence the player has already earned or can already observe.

The first bounded surface is dialogue-topic availability. Explanations must be downstream of the same eligibility evaluation that controls availability, and hidden/locked topics must remain hidden rather than becoming a spoiler list.

## Package 3 — Relationship-derived buildcraft

Qualify learned Traits as reusable semantic capabilities across more than one gameplay domain. Permanent Trait state remains the authority for durable capability ownership; the consuming domain remains the authority for local applicability; the player remains the authority for whether to choose the available action.

Strong Relationship state alone must remain insufficient for a Trait-only action when permanent Trait ownership is required.

## Package 4 — Third heterogeneous chapter

Use a third structurally different authored arc to test the small abstractions that survived the Rule-of-Two pass. Prefer an existing canonical relationship/content arc over speculative infrastructure. The chapter definition remains a projection over domain authorities rather than a parallel state machine.

## Package 5 — Copy strategy expansion

Deepen the incremental layer through player-authored priorities over already-qualified routine production tasks. Copies may automate understood, repeatable work; they must not autonomously choose irreversible narrative, social, faction, knowledge, world-state, travel, or combat decisions.

A first bounded version should preserve the one-active-task invariant and allow a player to define an ordered approved routine portfolio from which the Copy can start the first currently eligible routine.

## Stop conditions

Do not use this roadmap to justify:

```text
generalized ChapterEngine
generalized narrative DSL
open-world simulation
NPC schedule simulation
procedural narrative generation
generalized belief / rumor simulation
autonomous irreversible Copy planning
offline narrative/world progression
another GameLoop hardening milestone without a new observed bottleneck
```

## Evidence ceiling

Completion of this roadmap can establish repository behavior, contract consistency, backwards compatibility inside the qualified envelope, and deterministic composition. It cannot establish that players understand, enjoy, prefer, or value these features. Human product-quality evidence remains separate and explicitly unproven until actually collected.
