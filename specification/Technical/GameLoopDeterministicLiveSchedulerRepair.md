# GameLoop Deterministic Live Scheduler Repair — Package 2

**Package:** Deterministic Live Tick Scheduler Repair  
**Scope:** `REPOSITORY_ONLY` + `HERMETIC_VALIDATION`  
**Product authority:** unchanged; M26 remains unauthorized  
**Gameplay authority:** unchanged; default 10 Hz cadence, game-speed bounds, progression formulas, reward curves, and bounded offline settlement are not redesigned here

## Purpose

Package 1 deterministically reproduced three live-loop defects/risk conditions in `useGameLoop`:

1. fractional accumulator remainder was discarded when Redux tick updates caused the RAF effect to restart;
2. multi-step catch-up emitted duplicate callback tick identities because callback metadata was derived from render-captured `currentTick`; and
3. asynchronous `onTick` handlers could overlap when multiple fixed steps were emitted in one RAF callback.

This package repairs only those demonstrated scheduler behaviors and promotes the Package 1 characterization cases into regression invariants.

## Repair contract

### Stable RAF lifecycle

The live RAF callback reads scheduling configuration through refs rather than closing over the full changing GameLoop state. Redux `tick` rerenders therefore do not recreate the scheduler effect or reset the accumulator.

The accumulator is initialized when the live loop starts, then preserved across ordinary tick-driven rerenders. A 150 ms frame followed by a 50 ms frame at the default 10 Hz cadence therefore produces two logical 100 ms ticks rather than dropping the first frame's 50 ms remainder.

Pause/resume remains a live-time rejection boundary. Paused wall-clock time is not replayed through the fixed-step loop; the wall-clock anchor is refreshed across pause state transitions without converting the pause interval into gameplay progress.

### Monotonic logical tick identity

Each fixed step advances a local tick cursor before dispatch and uses that cursor for `TickData.currentTick`. Multiple fixed steps generated by one RAF callback therefore emit ordered identities such as `[1, 2]` rather than repeated render-captured identities such as `[1, 1]`.

Redux remains the persisted source of GameLoop state. The local cursor exists only to make same-frame logical-step metadata deterministic before React has rerendered.

### Serialized asynchronous tick work

`onTick` now explicitly accepts synchronous or Promise-returning handlers. Logical tick callbacks are queued in emission order.

- synchronous handlers continue immediately;
- Promise-returning handlers hold later callback work until they settle;
- later logical ticks cannot overlap an in-flight async callback; and
- a rejected handler is reported and the queue continues, so one rejected tick callback cannot deadlock subsequent already-emitted logical work.

The Redux fixed-step dispatch remains synchronous and is not made dependent on callback latency. This package does not add a catch-up cap, alter fixed-step duration, or reinterpret wall-clock absence.

## Hermetic regression matrix

`src/features/GameLoop/hooks/useGameLoop.timing-characterization.test.tsx` now asserts the repaired contract:

| Scenario | Required result |
| --- | --- |
| 100 ms at default 10 Hz | one 100 ms logical tick |
| ~60 Hz sub-step frames | accumulated frame time produces the expected fixed step |
| irregular 40 ms + 60 ms frames | one deterministic fixed step |
| 150 ms then 50 ms | fractional remainder survives rerender and reaches tick 2 |
| 250 ms at 10 Hz | Redux reaches tick 2 and callback identities are `[1, 2]` |
| slow async callback + 250 ms | second callback waits; peak callback concurrency remains 1 |
| rejected first async callback | rejection is contained and tick 2 callback still runs |
| pause/resume | paused wall-clock time is not replayed |
| `gameSpeed = 2` | existing fixed-step accumulation behavior remains |
| `tickRate = 20` | existing 50 ms fixed-step behavior remains |

All tests use the in-memory fake RAF/performance clock and require no credential, network service, production environment, deployment, or subjective review.

## Authority boundary preserved

This repair does **not** feed wall-clock absence through the live GameLoop. M21 bounded offline settlement remains the authority for offline progress. The rule remains: delegate grind, not judgment.

This package also does not decide whether the current tick rate, progression pacing, rewards, economy, unlock thresholds, tutorial behavior, or chapter pacing should change. Those remain product questions outside this scheduler repair.
