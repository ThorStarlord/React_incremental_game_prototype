# Universal Trait Ontology Reconciliation

**Status:** CURRENT — owner-directed bounded scope revision  
**Decision date:** 2026-09-28  
**Owner decision:** Traits return to a universal in-world ontology. Trait is broader than Capability; permanent assimilation means permanent availability; active expression determines current manifestation.

## 1. Why this reconciliation exists

Campaign One previously converged around a narrower operational identity:

~~~text
Relationship
-> qualifies learning
Trait
-> owns durable capability
~~~

That model successfully produced four relationship-derived cognitive capabilities and supported the recorded Campaign One feature-complete result.

The owner has now explicitly restored the broader original Trait-hoarder design direction:

~~~text
Traits are universal patterns of being.
Skills, physical patterns, knowledge, memories,
cognitive patterns, and metaphysical patterns
may all be Traits when salient.

Meaningful resonance with a source
-> gradual assimilation
-> Essence Stabilization
-> permanent availability
-> selective expression
~~~

This is an intentional scope revision, not evidence that the old milestone records were wrong when created.

## 3. Canonical glossary

### Trait

A discrete, stable, salient pattern of being.

### Capability

Something one or more currently expressed Traits make possible.

### Resonance

Alignment/contact that makes a foreign pattern legible and transferable.

### Discovery / Recognition

The protagonist/player recognizes that a pattern exists.

### Assimilation

Gradual reconstruction/internalization of the pattern.

### Stabilization

Essence-backed transition from reconstructed pattern to permanently available pattern.

### Assimilated Trait

A Trait permanently available to the protagonist.

### Expression

Current manifestation of an available Trait.

### Suppression

Removal from active expression without deleting assimilated ownership.

### Doctrine

Higher-order synthesis of assimilated cognitive/operational Traits that are currently expressed and deliberately foregrounded.

## 5. Universal ontology vs runtime representation

The world ontology may treat any stable pattern of a being as potentially Trait-like.

The runtime remains selective.

This revision does not authorize:

- serializing every body feature;
- serializing every fact;
- serializing every memory;
- a universal character-condition engine;
- generic continuous proximity simulation;
- automatic extraction from every nearby entity.

Only salient patterns should be authored as runtime Traits.

## 6. Trait nature is not provenance

Trait nature describes what the pattern is.

Examples:

- physiological;
- sensory;
- procedural;
- semantic knowledge;
- episodic memory;
- cognitive;
- dispositional;
- metaphysical.

Provenance describes how an instance came to exist.

Examples:

- innate;
- practiced;
- learned;
- relationship-assimilated;
- exposure-derived;
- modified.

The optional Trait identity metadata is deliberately open descriptive text rather than a closed runtime enum.

## 7. Domain-separation contract

Universal Traits do not absorb existing causal authorities.

### Relationship

Owns shared history, bond interpretation, Connection and relationship evidence.

### Relationship Memory

Owns meaningful historical evidence that something happened between characters.

### Memory Trait

If later authored, represents subjective episodic content instantiated in a mind. It does not rewrite history.

### Knowledge

Owns which NPC knows selected objective facts.

### Knowledge Trait

Represents a salient body/model of semantic information, not every known fact.

### Routine familiarity

Owns the delegation proof that the protagonist personally understands a repeatable routine.

### Procedural Trait

May represent skill/knowing-how, but does not automatically establish delegation mastery.

### Faction Reputation

Remains institutional standing.

### World State

Remains persistent objective world/regional condition.

## 8. Relationship-mediated assimilation

Campaign One retains the existing evidence machinery:

- authored discovery;
- Relationship Experiences;
- assimilation progress;
- compatibility;
- Connection qualification;
- landmark Memory evidence;
- authored final event.

The fictional cause broadens:

~~~text
proximity
+ attention
+ emotional / relational significance
-> Resonance
-> pattern legibility
-> Assimilation
~~~

Positive affection is not required.

Conflict, rivalry, obsession, dependence, vulnerability, teaching, and mutual calibration may all create meaningful resonance.

Lyra remains the canonical adversarial example.

## 9. Continuous-proximity non-goal

No generic NPC × Trait × time simulation is introduced.

Campaign One continues to use authored Experiences as bounded evidence for meaningful periods of proximity, attention, practice and conflict.

A continuous system requires a later demonstrated product need.

## 10. Assimilated library and expression

The previous rule:

~~~text
permanent Trait
-> always active
-> no slot required
~~~

is superseded by:

~~~text
assimilated Trait
-> permanently available

expression slot
-> currently active / manifested
~~~

Direct Player-stat effects apply only while expressed.

Semantic authored Trait capabilities are available only while expressed.

An assimilated but suppressed Trait is still owned and may be re-expressed freely when capacity allows.

## 11. Expression swapping

Player Trait slots become expression capacity.

Current policy:

- expression/suppression is freely player-owned;
- no NPC proximity is required;
- no generic swap currency or cooldown is required;
- Campaign One starts with two expression slots so the first two-Trait Doctrine is legal;
- later Resonance levels expand capacity up to the existing maximum;
- one Trait pattern cannot occupy multiple Player expression slots simultaneously;
- discovered temporary patterns remain expressible under the bounded existing Campaign One rule;
- stabilized patterns remain in the assimilated library when suppressed.

## 12. Stabilization authority

Stabilization may occur when the Trait has a qualified live authority:

- direct Player-stat authority;
- named runtime authority;
- semantic capability authority.

Deferred-only historical metadata remains insufficient.

This intentionally changes the former rule that named-runtime-only Traits such as Essence Flow could not become permanent Player Traits.

Under universal ontology, a real pattern may be assimilated even when its current useful expression is primarily through sharing/another named runtime.

## 13. Source provenance

The generic Trait source field can now identify non-NPC provenance.

Therefore Relationship gating applies only when:

- sourceNpc is explicit; or
- a legacy source value resolves to an actual NPC.

A relic/place/event source must not accidentally require NPC Connection.

## 14. Sharing

Sharing authority now follows expression:

~~~text
expressed Trait
-> share/project allowed where target rules permit

suppressed Trait
-> not shareable

assimilated vs temporary
-> does not by itself determine shareability
~~~

Sharing does not transfer permanent ownership to the target.

Stabilization must no longer automatically unshare a Trait that remains expressed.

## 15. Doctrine

Current Doctrine definitions retain the historical requiredPermanentTraitIds field.

Current semantic rule:

~~~text
required Trait
must be assimilated
AND expressed
AND foregrounded
-> Doctrine active
~~~

Doctrine adoption/switch is itself an explicit Player expression decision and atomically places the Doctrine pair into the first two unlocked slots. Replaced Traits remain assimilated.

It fails only if the required Doctrine pair exceeds unlocked expression capacity.

## 16. Authored Quest / Dialogue / Combat compatibility

Existing authored content still carries requiredPermanentTraitIds.

A large content-data rename is not necessary for this bounded migration.

Current runtime interpretation:

~~~text
requiredPermanentTraitIds
= compatibility key for Trait pattern(s)
  that must currently be expressed
~~~

This makes expression/loadout choice consequential while preserving authored IDs and historical content.

## 17. Save schema v3

The scope revision changes player build semantics, so save schema advances from v2 to v3.

### v2 -> v3 migration

Preserve:

- permanentTraits exactly as assimilated ownership;
- existing slot contents;
- doctrine focus;
- all unrelated state.

Then fill unlocked empty expression slots deterministically:

1. doctrine-focus Traits first;
2. remaining assimilated Traits in saved order;
3. skip already expressed IDs;
4. never invent Trait ownership;
5. never discard an assimilated Trait when capacity is insufficient.

An assimilated Trait that cannot fit remains owned but suppressed.

## 18. Cross-category universality proof

The bounded implementation proves the ontology through existing catalogue content rather than adding speculative Campaign One content:

- Willow's Wisdom — cognitive;
- Resilient Constitution — physiological;
- Battle Hardened — procedural;
- Tome of Forbidden Knowledge — semantic knowledge;

This is enough to demonstrate that the runtime Trait type is not capability-only.

No Memory Trait is fabricated merely to satisfy a taxonomy checklist.

## 19. 27-Trait catalogue reconciliation

Universal ontology does not automatically validate every legacy definition.

Current direction:

- preserve compatible active stat/capability patterns;
- permit live named-runtime patterns to stabilize;
- keep deferred metadata inert;
- reinterpret artifact-like names only when content warrants it;
- do not resurrect cut generic Skills/Crafting systems;
- do not mass-delete compatibility IDs.

Relationship-gain multipliers remain particularly weak fits because they manipulate relationship state rather than describe a stable transferable pattern.

## 20. UI contract

Player-facing Trait surfaces must distinguish:

~~~text
Discovered
Assimilating
Assimilated
Expressed
Suppressed
~~~

The minimum currently implemented distinction is:

- discovered availability;
- relationship assimilation evidence where applicable;
- Stabilization;
- assimilated library;
- expressed Trait slots.

Player surfaces should stop teaching:

- permanent = always active;
- stabilization frees a slot;
- permanent Traits cannot be shared;
- NPC proximity is required to swap expression.

## 21. Qualification invariants

The universal Trait package is not complete until deterministic tests prove at least:

1. assimilated ownership survives suppression;
2. active stat effect depends on expression;
3. a suppressed assimilated Trait can be freely re-expressed;
4. expression cannot duplicate the same Trait in multiple Player slots;
5. a non-NPC source does not trigger NPC Relationship gating;
6. named-runtime-only live patterns may stabilize;
7. deferred-only metadata cannot stabilize;
8. Stabilization spends Essence once;
9. Stabilization preserves current expression;
10. sharing accepts expressed assimilated Traits;
11. sharing rejects suppressed Traits;
12. Doctrine requires assimilated + expressed + foregrounded components;
13. authored Quest/Dialogue/Combat gates consume expression;
14. v2 save migration preserves all assimilated ownership and deterministically restores expression;
15. full Campaign One regression remains legal;
16. production build passes.
