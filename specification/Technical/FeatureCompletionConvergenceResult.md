## What the repository learned

### 1. Feature depth is about differentiated retained value, not subsystem count

Candidate B reached its bounded exit with two materially distinct standing
responsibilities:

- Archive Verification: epistemic/source-verification work with contradiction
  exceptions;
- Forge Assistance: physical/institutional upkeep with structural-deviation
  exceptions.

Both preserve player-owned judgment when work leaves the known envelope. A third
standing responsibility would add count, but the current evidence does not show a
new player role that justifies it.

**Learning:** stop conditions should be expressed as distinct player value and
behavioral coverage, not "one more example."

### 2. A capability becomes part of a build when it remains useful outside its pair

Candidate A initially risked making durable relationship-derived Traits feel like
ingredients that only matter when paired into a doctrine.

The qualified package gives `ConstraintSense` and
`AdversarialCalibration` independent late-campaign GC09 judgments after their
GC08 uses, while the existing doctrines remain selectively meaningful in
GC06/GC08/GC10.

**Learning:** durable capability identity is stronger when a capability has repeated
single-capability consequences as well as emergent paired specialization.

### 3. Authored composition can satisfy strategic depth without a generalized simulator

Candidate C's exit shape already exists in GC08-GC10. Late campaign decisions
compose independently-owned Relationship, Knowledge, Faction, World State, build,
and delegation evidence. The fortified finale path, for example, requires
relationship history, committed Knowledge, world-state posture, and City Watch
standing without collapsing those authorities into one score.

**Learning:** heterogeneous authored composition is sufficient when several
independent authorities materially constrain one decision. A generic strategy
engine is not automatically deeper.

### 4. Deterministic qualification and human product evidence answer different questions

Build Validation #477 proves that the exact Candidate-A head satisfies the
repository's deterministic integration and regression contracts. It does not prove
fresh-player comprehension, pacing, fairness, enjoyment, emotional impact,
preference, or desire to continue.

**Learning:** a completed repository construction lane can coexist with
`HUMAN-UNVALIDATED`. Do not keep building merely because human evidence is still
open, and do not promote human claims merely because CI is green.

### 5. A maturity transition must update the active authority, not only the package record

The A/B/C sequence was converged before every top-level document stopped calling
Candidate A or Feature Completion the active frontier. That stale wording could
legitimately route a future agent back into already-completed work.

**Learning:** when a frontier closes, update the status header, authority index,
handoff, roadmap, and tracker in the same transition package. "Result recorded"
is not enough if the re-entry path still points backward.

### 6. Beta scope lock is not a repository freeze

Once Feature Completion is reached, new product pillars and speculative feature
expansion are closed by default. However, concrete deterministic, heuristic,
synthetic, accessibility, reliability, presentation, pacing, balance, persistence,
and release-readiness findings may still justify bounded repairs inside the locked
1.0 scope.

**Learning:** Beta should narrow the kinds of changes allowed, not prohibit
repository-owned improvement while genuine human evidence is being collected.

## Construction stop rule

Do not reopen Candidate A, B, or C merely because another implementation is
possible.

A new feature-depth package requires one of:

1. accepted human evidence showing a repeated product failure that cannot be
   repaired locally;
2. deterministic or synthetic evidence of a concrete Campaign One requirement
   failure;
3. a newly discovered contradiction in current feature authority;
4. an explicit scope/governance revision.

Otherwise route work to the Beta contract:

```text
comprehension / discoverability
UX / feedback / terminology
pacing / balance
accessibility / presentation
save / recovery
reliability / performance
supported-browser behavior
release qualification
```
