qualification artifact is not silently treated as a pass.

| KD-009 | Moderate / presentation-authority | Player-surface prototype/debug residue | Resolved | Normal Campaign One pages exposed prototype/debug wording or controls: manual prototype Essence generation, NPC relationship debug mutations, deferred Equipment wording, internal tick counters, no-op Settings import/export, and an unreachable legacy reset page. | Closed by PR #139; exact head `4a64d8d53aea1a9c3385894ac89af570dec778d7` passed Build Validation #419 / run `35680087869` before merge to `main`. GC-01 regression coverage now rejects recurrence. |
| KD-010 | High / campaign integrity | Startup catalog race | Resolved | Pressing New Game (or Continue/Load) before the startup NPC/quest catalog loads finished let the late result overwrite the session: a fresh game revealed all seven NPCs out of campaign order, and a loaded save could lose its NPC and quest progress. Found by RC-qualification synthetic UI probing (SYNTHETIC_FINDING), reproduced in 2/2 immediate-click runs. | Startup loads are now non-destructive: the NPC catalog never replaces an established session world, and startup quest loading uses `preserveExisting`. `StartupCatalogRaceRegression.test.ts` reproduces both orders and runs in Build Validation. |
| KD-011 | Moderate / accessibility | New Game intro narration | Resolved | The required intro rendered inside an `aria-hidden` MUI Backdrop, so its Continue/Begin action was invisible to assistive technology. | The intro is now a modal Dialog named "Introduction" with initial focus on its action; browser qualification confirms it by keyboard (`intro-dialog-keyboard-confirmation`). |
| KD-012 | High / campaign integrity | Page reload mid-game | Resolved | Reloading the page (or opening any `/game` URL) without New Game or Load showed the uninitialized startup world: all seven NPCs, the intro again, and no save. Continuing to play there broke the campaign, and autosave could persist it. | Sessions are now explicit (`meta.sessionActive`, set by New Game and Load). Game routes without a session return to the main menu, where Continue resumes the latest save. `GameSessionLifecycle.test.tsx`. |
| KD-013 | High / persistence | Save actions and autosave scope | Resolved | The game had no in-game save and no way back to the main menu (the canonical load/import/export surface). Autosave ran on the main menu too, so idling there wrote a non-session save that Continue would then load. After a load the session reported "Not saved yet". | In-game **Save Game** and **Save & Main Menu** use the canonical `saveGameThunk`; leaving the page writes a rolling autosave; autosave runs only during a session; Load records the loaded save's time. No separate save-management page was added. |
| KD-014 | High / persistence | Autosave accumulation | Resolved | Each save stores the whole session (~175k characters at New Game) and every 5-minute autosave created a new slot, so roughly 28 saves would exhaust localStorage during a long campaign and every later save would fail. | Autosaves keep a rolling set of the newest 3 (`pruneAutosaves`); player-named saves and imports are never pruned. |
| KD-015 | High / presentation + accessibility | Main menu and save dialogs | Resolved | The main menu button list and the Export, Import and Delete save dialogs were written with Tailwind classes, but Tailwind is not installed. Players saw unstyled browser-default buttons, the Export dialog rendered inline under the page overlay so its Close and Copy buttons could not be clicked, and the subtitle and shortcut legend were near-black on the dark background. | Rebuilt the button list and the three dialogs with MUI (the project's UI library): real modal dialogs with titles, labelled fields and named close buttons; fixed light text on the dark menu. The full-campaign run now exports the completed save, imports it, and loads it. |
